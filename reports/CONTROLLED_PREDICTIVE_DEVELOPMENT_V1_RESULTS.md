# 受控预测商：首个开发结果（2026-09-08）

这次开发切片找到了有用的有限压缩：在三个公开标准 4×4 2048 棋盘、三步 horizon 内，经验商的活跃状态由 211 减到 35，并且三个查询的 lifted policy 都取得精确有限模型的最优目标值。原始小报告为 [controlled_predictive_development_v1.json](controlled_predictive_development_v1.json)。

这是对新建模对象的开发观察。U005 的科学 FAIL 和 U006 的不可运行状态保持不变。

## 实际范围与运行

默认命令完成一次，退出码 0，报告状态 `DEVELOPMENT_COMPLETE`。报告约 61 KB；没有保存或拉取完整轨迹、矩阵或 checkpoint。

- 公开棋盘：`last_pair_spawn_risk`、`dense_merge_choice`、`adjacent_1024_goal`，完整棋盘秩编码随 JSON 保存。
- 闭包：2,845 个分层状态，其中 211 个活跃决策状态、2,576 个 horizon 截断状态、18 个 LOST、40 个 WON。
- 所有合法动作与生成结果：777 个转移行、4,322 个 exact outcomes。
- 经验数据：每行 64 次采样，共 49,728 次；完整状态经验基线与候选商共享这一次采样结果。
- 三个查询：合并收益、收益减失败惩罚、收益加目标奖励减失败惩罚。各模型只构建一次，随后复用。

实现的 13 项针对性测试全部通过，包括动作相反但最优价值相同的状态分离、两步风险冲突、概率质量、终态事件、采样未覆盖路径上的策略完整性、标准 2048 全动作闭包和报告集成。独立只读代码审查未发现本次范围内需修复的实质问题。

## 压缩与规划工作

| 模型 | 活跃状态/cells | 动作行 | 后继项 | 编译模型 JSON bytes | 棋盘＋horizon 映射 bytes |
| --- | ---: | ---: | ---: | ---: | ---: |
| 完整状态经验模型 | 211 | 777 | 4,031 | 500,091 | 121,314 |
| 新受控预测商 | 35 | 112 | 159 | 27,101 | 114,011 |
| 精确 reference quotient | 75 | 263 | 374 | 43,805 | 114,128 |
| 动作后果打乱商 | 35 | 112 | 159 | 27,098 | 113,995 |

候选相对同信息量经验基线减少了 83.4% 的活跃状态、85.6% 的动作行、96.1% 的后继项。每次 DP 实际处理这些活跃状态及全部动作行；为保证策略在精确审计可能进入的状态上有定义，处理范围包括所有编译 cells。终止及 horizon-zero cells 的大规模合并没有被用来夸大活跃状态压缩。

编译模型大小包含 cells、成员整数 ID、转移和经验直径；真正从棋盘编码还需要右列映射。整数 ID→cell 与棋盘→cell 两种 lookup 在 JSON 中分别计量，不能当作 RAM 实测。候选仍保留完整覆盖状态的查表编码，映射存储没有随活跃 cell 数量等比例减少。

## 计划质量与预测误差

三个查询下，候选商、完整状态经验模型和精确 reference 的 lifted-policy 目标值都等于精确全状态 comparator；各个根节点也保持该范围内的最优值。候选预测并非完全准确：

| 最大绝对预测误差，跨三个根与三个查询 | 完整状态经验模型 | 候选商 | 精确 reference |
| --- | ---: | ---: | ---: |
| 累计合并收益 / 2048 | 0.00025635 | 0.00025635 | 0 |
| 失败概率 | 0.021875 | 0.023299 | 0 |
| 成功概率 | 0 | 0 | 0 |
| 对应查询的标量目标 | 0.109631 | 0.109631 | 0 |

目标误差较大的项来自失败惩罚放大概率误差。候选在这些查询上保留了足够好的动作选择，不代表其任意计划预测都精确，也不代表风险校准优于完整状态经验模型。

动作后果打乱组有相同 35 个活跃 cells 和 112 个动作行，却在三个查询上的实际平均目标分别落后精确 comparator 0.089120、0.122453、0.255787（对应合并收益、失败敏感、目标及失败查询）。其最大失败概率预测误差为 0.078125。这表明压缩规模本身不能解释当前质量；这次开发实例能检出被破坏的动作语义。

将所有状态 ID 与插入顺序反向重命名，候选的分割保持相同，三个查询的根预测差为 0。该控制只检验无语义 ID 编码，未检验图像、棋盘旋转或学得的动作 correspondence。

## 成本与下一步判断

本次单次计时：公共精确闭包约 497 ms，共享采样约 14 ms。经验全状态模型构建约 6.06 ms，候选商构建约 39.15 ms；三个查询合计 DP 时间约 5.21 ms 与 0.346 ms。预测分项评估、精确审计、序列化计量和重命名控制的成本在 JSON 中分别记录。

因此，规划遍历减少了，但这三个查询尚未抵消更贵的候选构建：仅“构建＋三次 DP”约为 11.28 ms 与 39.50 ms。这里没有建立总成本优势或 break-even；亚毫秒的单次时间也不足以作为稳定速度结论。

精确 reference 在有限范围内有压缩且无预测误差，说明这些实例确实存在保持受控后果的商空间。候选进一步压缩而保持本次决策质量，支持继续研究受控预测分割；原玩家技能识别失败不再充当新方向的唯一验收指标。

后续开发应首先扩展公开开发状态的风险/收益权衡和 horizon，检验不同查询是否需要不同策略，并减少覆盖查表与分割构建成本；用独立开发样本研究风险校准。扩展不应沿用本次成功点作为独立确认。正式后继需要新的冻结方案和独立数据。

## 限制

三块手写密集棋盘、短 horizon 和可枚举的精确 mechanics 是有意限定的开发设置。查询较少，尚未代表自然开局、完整游戏、未见状态或未见查询族。模型复用在本地内存完成；当前报告没有交付可在另一个进程直接加载的生产模型。经验分割并非统计或 sound envelope，当前尚未接入生产 CEGAR、局部恢复或 chance-constrained planner。未得到 U005 失败机制的因果定位，也没有完成新方法的独立科学确认。
