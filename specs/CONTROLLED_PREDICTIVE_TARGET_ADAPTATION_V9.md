# V9：目标经验观测触发的局部可执行规则适配

本协议先于 V9 开发实例的适配和结果固定。V8 的来源经验约束已经满足，但冻结规则在目标中仍有动作后果失配。本轮检验来源规则作为初始分组，是否能减少目标建模成本；研究对象明确为目标数据适配。

## 固定输入与信息范围

[V9 名册](../reports/controlled_predictive_cohort_roster_v9.json)原样沿用 V8 的 16 个根、四个场景和角色：主场景使用原三个变体 0 作来源、评估全部 16 例；三个 LOFO 场景各以另外两个机制族的变体 0 作来源，评估两个来源与目标族全部四例。合计 34 个场景／实例，每个种子均运行全部项。角色中的 TRAIN／FAMILY_HELD_OUT 等描述来源拟合范围；适配方法允许使用每个当前目标的经验观测。

每动作行固定 256 次观测，种子 `832101,832102,832103`，原六查询库加四探测查询、原 horizon 与 30,000 状态完整闭包上限不变。无新棋盘、参数扫描或结果筛选。超预算及未解决签名冲突全部留存；V2 原 24 个延期最终候选继续不进入本轮。

每个原始实例／种子只创建一个经验核，供全部场景和方法复用；闭包每例只构建一次。来源编码器为 V8 的经验预测约束学习器，每场景／种子拟合一次，合计 12 次。学习器仅接收声明来源的经验核与棋盘。适配和从头目标学习只接收当前目标经验核、棋盘与所需来源规则，不接收查询、精确 Q 或最优动作。

所有实例和机制均为已暴露开发材料。主场景与整族留出分别统计，不视为独立确认。

## 适配规则

使用 V8 原有 31 个特征与终态、合法动作、horizon 语义。对当前目标只计算一次棋盘特征并缓存到构建结束。来源编码器保持不可变，每个目标生成自己的独立规则森林。

按 horizon 自底向上，对每个目标状态构造各动作的经验平均奖励和已完成适配的后继编码分布。分组由原来源输出编码决定；即使来源树的多个叶位置输出同一编码，也把其全部当前目标成员作为一个单元处理。

- 单元的全部目标经验签名相同：保留原编码，不增加分割。
- 单元包含不同目标签名：使用 V8 的不兼容对优先轴向分割规则，最小叶 1，无额外深度限制。
- 发生实际分割时，所有子编码使用高于该强制分组全部原编码的新编号，包含目标没有访问的原编码；相同纯签名在这一个细分单元内部可以复用子编码。
- 分割规则插入到输出同一原编码的每个原叶位置，保留原祖先分割。不同原输出编码之间不合并。
- 目标未访问的原输出编码保留；一个未访问的叶位置若与已细分单元共享原输出编码，则同样接受该单元的补丁。
- 来源不存在的强制分组从固定常量编码 `-1` 开始，按同样规则检查、必要时分割，并保存为目标可执行树。另报适配前的来源未见分组使用量。
- 如果全部特征相同、经验签名却不同，保留未解决叶及其特征／动作包络；不添加棋盘或状态 ID 查表。

来源分区只细分不合并，因此最终模型可能比从头学习和最小精确经验商更细。低层编码改变后，上层目标使用最终低层编码重新生成；任何低层未解决冲突均阻止全局递归经验约束通过。

本版局部性指只有冲突单元新增规则分割。全部目标状态和动作行仍参与一次一致性检查，最后按最终编码统一编译一次有限动力学。没有复用旧编译转移行，不声称已经实现增量动力学更新。检查、树复制／改写、全部最终聚合成本均计入。

## 从头学习与六组比较

从头目标规则使用同一个构建引擎，以空来源规则森林为起点；它与来源适配共用一次目标特征计算、完整签名检查、分割准则及最终一次编译。这样不把重复特征提取的实现差异当作来源初始化收益。

六组固定为：完整状态经验模型、零容差精确经验商、原来源规则冻结使用、从头目标规则、来源规则目标适配、适配后动作后果打乱控制。所有组的当前目标观测完全相同。从头目标规则不需要来源拟合成本。

控制组先复用目标适配所得编码，再逐状态循环移置合法动作的整条观测行并编译，不在打乱观测上重新适配。由于该依赖，轮转前五组的执行顺序，控制组最后构建；六组全部十查询策略冻结后，再生成精确最优参考和真实冻结策略审计。

报告根首动作、根完整策略、全部活跃状态策略、收益／失败／成功预测、必要查询切换、相对完整状态的新增目标损失、同 cell 动作冲突及实际状态反例。另直接比较适配与从头目标方法的策略后果和成本。最坏绝对损失与最坏新增损失分开。

目标适配诊断包括初始／最终单元数、适配前来源未见分组、冲突原编码、已细分编码、增加的树节点、保留的纯单元、未解决冲突、实际树深度和各阶段时间／工作量。对保留的同特征经验冲突状态，从现成精确审计中附上十查询最优动作集合，解释是否存在真实决策冲突；标签不参与适配。

## 成本与运行产物

每个场景报告 1／6／10 查询工作量。来源拟合对冻结来源、来源适配和控制各作为一次可复用准备成本，按场景声明的 16 或 6 例摊销；全轮实际只执行每场景／种子一次来源拟合。从头目标、完整状态和精确经验商不承担来源规则拟合。

单目标另报独立承担全部来源闭包、来源观测和完整拟合的成本；当前目标若也是来源，则其观测已计入当前成本，不重复加计。经验库和闭包的实际总成本只记一次，跨场景逻辑读取另列。

适配与从头方法的构建时间包含全部目标检查、规则生成和一次最终模型编译。控制组的实际新增工作为打乱及按既有适配编码编译；单独使用控制方法所需的目标适配准备也在其工作量表计入，但全轮实际成本不能把共享适配重复加总。精确参考、库存序列化和事后解释继续单独计时。

固定导出主场景、种子 832101、`v6_spawn_edge_rescue_2` 的目标适配模型，沿用 V7 可执行规则文件格式。保存树、有限转移、编码到 cell 对照及一个例子根，不保存完整棋盘／ground 状态映射。单独进程以收益 1、风险 0.3、目标 0.2 查询一次，与进程内同一模型比对；这仅验证交付一致性。

## 执行与判断

先用针对性测试检出共享编码漏修、源规则被修改、空区域编码碰撞、低层变化未传至上层、同特征冲突被隐藏、从头目标实现不公平、目标或精确标签进入错误拟合阶段，以及观测／适配准备重复计费等实现错误。测试通过后执行一轮冻结比较，保留所有结果，不追加调参运行。

若策略恢复但适配比从头建模更慢，不能称来源初始化节约成本；若同样本基线也错，保留采样误差。若新目标同特征冲突出现，仅按所留真实动作证据判断表示不足，不把经验频数不同直接解释成机制不同。默认基线为均匀采样＋精确经验商，是否存在适配收益以匹配结果为依据。
