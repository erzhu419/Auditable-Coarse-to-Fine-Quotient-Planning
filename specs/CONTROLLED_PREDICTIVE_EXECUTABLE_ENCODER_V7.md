# V7：冻结规则编码器与同样本有限规划比较

本协议在 V7 编码器拟合和候选结果产生前写入。目标是让一个学习后固定的规则直接将棋盘编码为有限符号，在未参与规则拟合的开发实例上构建经验动力学并重复规划。V6 精确商仍是查表上限，本轮开始检验可执行编码规则。

## 固定数据和拆分

保留完整 V6 的 15 个实例，并加入 V3 已暴露的 H2 后续决策回归 `exposed_left_successor_7`，合计 16 个。V6 三个机制族分别按固定变体编号拆分：

- 变体 0：`TRAIN`，共 3 个根，参与编码器学习。
- 变体 1：`VALIDATION_DIAGNOSTIC`，共 3 个根，作为冻结模型后的诊断。
- 变体 2、3：`FIT_HELD_OUT_DEVELOPMENT`，共 6 个根，不参与编码规则拟合。
- 三个 V1 公开对照与旧 H2 回归：`EXPOSED_REGRESSION`，共 4 个根。

本轮只有一套固定的特征与树参数，不做候选选择或根据诊断组调整参数。全部实例已经被 V6 或更早的精确开发结果暴露；“未参与拟合”仅描述本轮训练使用范围。一个机制族的变体也不构成不同机制的独立重复。

[执行前名册](../reports/controlled_predictive_cohort_roster_v7.json)先写入。各实例完整闭包最多 30,000 状态，超预算实例保留；不截断、不更换实例。利用现成闭包，在拟合前比较原始棋盘及旋转／反射关系，记录跨组重叠；如存在重叠，按实际暴露范围报告，不删除实例或把重叠称作未见状态。V2 原 24 个延期候选不进入本轮。

## 查询无关的规则学习

编码首先保留剩余 horizon、终态语义和合法动作集合。状态为 WON、LOST 或 CUTOFF 时单独编码；ACTIVE 状态按合法动作集合分组。它们从棋盘和剩余步数直接计算，不依赖状态 ID。

每个 ACTIVE 分组学习一个二叉规则树。固定特征为棋盘空位数、最大 rank、rank 1／2／10 的数量、水平／垂直相邻相同非零砖块对数，以及四个方向确定性滑动后的合并奖励、空位数、相邻对数、邻接 rank 1／2 的空位数。合并奖励单位为分数除以 2048。特征不包含完整 16 格 rank 向量、棋盘 ID 或最优动作标签。

特征可执行四方向确定性滑动，相关操作与成本计入编码。它不枚举随机生成结果、不读取真实转移概率，也不进行多步 ground 搜索。

训练按剩余 horizon 从低到高进行。每个训练状态的目标向量，包含每个合法动作的经验平均奖励，以及观测后继经过已固定低层编码规则后的符号概率分布。二叉分割贪心最小化这些坐标的平方误差和；状态等权，奖励与每个概率坐标权重均为 1。参数固定为最大深度 4、每个子叶至少 2 个训练状态、最小正平方误差增益 `1e-12`。特征及阈值的并列使用确定顺序处理。

终态和没有训练样本的合法动作／horizon 分组使用常量符号；后者是新输入的固定行为，单独报告使用情况，不临时插入状态查表或根据评估数据新增规则。编码器保存特征规则、分割阈值及叶编号，不保存训练棋盘字典。

每个采样种子仅在三个 TRAIN 经验模型上拟合一次规则。其余实例的经验数据不会进入训练；规则冻结后才取得该种子的其余实例观测。十个规划查询全部不参与规则拟合。

## 同样本动力学与四组比较

三个采样种子固定为 `832101,832102,832103`，每个合法动作行均匀读取 256 次观测，不运行新的样本量或参数扫描。训练实例的经验核在本身的开发检查中直接复用，不重新采样。

每个实例／种子的同一个经验核用于四组：

1. 完整状态经验模型。
2. 零容差精确经验商。
3. 冻结规则编码器：对当前棋盘直接编码，将相同编码的状态按相等观测量聚合为经验动力学。
4. 动作后果打乱控制：在每个状态的原合法动作之间循环移置整条观测行，使用同一套冻结编码分组构建模型。

当前动力学在每个实例上重新估计一次，再供十个查询复用。这检验固定编码规则的开发迁移，不是动力学零样本迁移。控制组不重新拟合编码器。

沿用六查询库及四探测查询：收益权重 1；六查询为风险 `0,0.05,0.2,1,5`／目标 0，另加风险 1／目标 1；四探测查询为风险 `0.1,0.5,2`／目标 0，另加风险 0.5／目标 2。这些都是已暴露开发查询，本轮不声称探测查询是独立确认。

每个实例的四组十查询策略先冻结，再生成精确最优参考和真实冻结策略审计。报告根动作、完整策略损失、收益／失败／成功预测、全部活跃状态质量、严格查询切换、相对同样本完整状态模型的额外损失，以及实际状态／动作反例。若完整状态经验模型也错误，分别报告共同采样错误和编码新增错误。

## 信息与成本范围

四组的当前实例转移观测相同。编码器另外使用三个来源的训练观测；这些来源数据对基线也可用，但完整状态与精确经验商不利用它们拟合可迁移规则。因此不声称全部来源信息使用或总成本完全相同，也不将编码学习成本省略。

分别记录闭包、当前观测、特征与规则计算、动力学构建、规划、预测、真实审计、训练来源获取和树拟合成本。完整工作量计入一次编码器拟合；训练实例观测复用时不重复计费。另给出单个未参与拟合实例若需独立承担全部来源成本的总工作量，以及在声明工作量内分摊训练成本的结果。来源开销不隐藏在查询时间里。

保存源规则 JSON 大小、当前编译模型与编码到 cell 对照的大小。构建和审计可以使用临时状态 ID 映射，运行时交付不保存完整棋盘／状态 ID 查表。对构建、编码和查询给出实际工作计数；时间是当前机器上的单次开发测量。

## 可执行交付与验证

固定导出实例 `v6_spawn_edge_rescue_2`、采样种子 `832101` 的规则模型。交付包含学习后的编码树、有限 cells／动作转移及编码到 cell 对照，去掉 ground 成员和状态 ID 映射。例子只携带一个查询根棋盘，不携带全部棋盘库存。

在单独进程从该文件加载模型，直接编码这个未参与规则拟合的根棋盘，并运行数值查询：收益 1、风险 0.3、目标 0.2。核对动作、模型预测值与同一冻结模型的进程内结果一致。这项检查只证明保存／加载与模型推演一致，不证明新查询的真实策略最优。

针对性测试检查：规则不依赖棋盘字典；经验后续差异可以影响学习分割；终态、合法动作和 horizon 保留；评估数据不进入拟合；四组共享当前观测；真实答案在策略冻结后使用；同 cell 观测聚合正确；超预算实例留存；运行时文件不包含完整 ground 映射并能重载推演。对应实现错误先修复，再执行一次科学比较。

本轮只执行这一套比较及一次保存／加载检查，不并发其他科学实验，不按候选结果调整特征、深度、阈值、拆分或样本量。旧负面结果、U005 科学 FAIL、U006 未运行和 V2 延期集合状态保留。
