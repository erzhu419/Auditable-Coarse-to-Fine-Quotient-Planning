# K7 H1 Production Lifecycle Source Candidate V1

Status: content-addressed, unanchored construction candidate; not a production
source or execution authority.

Proposed contract: `2.0.58-D`

Profile key:
`construction_k7_h1_production_lifecycle_source_candidate_v1`

## Closed construction claim

The module
`src/acfqp/construction_k7_h1_production_lifecycle_source_candidate_v1.py`
defines one ordered candidate transition/site table. The same transition tuple
is the sole input to:

1. candidate-event-prefix replay; and
2. exhaustive first-failure-prefix analysis.

The manifest binds the complete module bytes, a normalized AST digest, and the
exact line spans and byte digests of the site generator, transition compiler,
replayer, analyser, and canonical verifier. Changing source bytes, deleting or
reordering a transition, deleting a failure branch, or changing a dependency
identity changes or invalidates the candidate. Because this identity is minted
from the currently imported module and has no external preregistration anchor,
it proves content consistency only; a fresh import can mint a different
candidate and it is not production source authority.
The candidate uses a dedicated candidate content domain. The reserved authority
domain is never used, and every legacy authority-named accessor/verifier fails
closed instead of returning the candidate.

Relative to the hand-declared candidate table, the lifecycle lists, in order:

1. route-wide BROKER+WORKER+BUSINESS memory binding;
2. the three preflight common checks;
3. whole-route output reservation;
4. every registered sealed-input stage and mount-open admission;
5. WORKER launch, its sealed-input reads, BUSINESS launch, and its reads;
6. BUSINESS/BROKER/WORKER business-result reads;
7. exact known-descendant reap;
8. retained-same-OFD `memory.peak` read;
9. every mount cleanup in reverse-open order;
10. every registered output-role readback;
11. route-wide output finalization and owner close.

Both WORKER and BUSINESS launch sites have an explicit native-existence
ambiguity edge. Every stage, read, and mount-open admission has a distinct
pre-side-effect cap-rejection prefix. Callback failure, observed-overrun,
cleanup failure, and protocol failure edges are declared only where their
operation semantics permit them. Branch count is derived as
`1 + sum(failure edges over transitions)`; it is not copied from a fixture.

Each branch records, for every one of the nine shared paths in that table,
attempted, admitted, completed, and unreached site partitions. This is a total
partition of the candidate table only. It is not evidence that the table covers
all production source sites or their multiplicities. Missing sites are never
interpreted as zero and wildcards are forbidden.

These are first-failure prefixes only. The cleanup continuation after an
initial failure is not yet generated by this program, so it does not enumerate
complete failed-attempt branches and cannot by itself provide a route operand.

## Explicit non-claims

The current live BROKER/WORKER/BUSINESS runtime is not yet bound to this table.
Its intended owner methods are strings, not a semantic binding to the shared
cap owner, so owner-order compatibility is not claimed. Common-check
multiplicities are hand-selected rather than derived from production source
sites. The output DAG has multiple role-presence leaves, while the linear table
reads all eight roles; the leaf-specific join is not bound. The upstream
execution topology is construction-only, native callback facts and native
existence resolution are absent, native extents and physical instance
identities are unbound, persistent cross-process single-consumption receipts
are absent, and the production serializer remains a candidate. The
post-first-failure cleanup-continuation program and the route/stage meaning of
fallback cap exhaustion are also unbound. A first failure is only a provisional
cause; it issues neither attempt closure nor terminal classification.

Therefore this contract issues none of the following:

- production execution authority;
- a numeric shared operand or any numeric ceiling;
- a formal V7 route upper or route decision;
- shared receipts or CounterRecords;
- a WorkVector or ComparisonVector;
- a Gate result.

The locks remain:

```text
official_execution_allowed = false
official_scalar_cost = null
official_N_break_even = null
COUNTER_COMPLETENESS_GATE_NOT_RUN
WORKLOAD_ECONOMICS_GATE_NOT_RUN
SAMPLE_EFFICIENCY_GATE_NOT_RUN
```
