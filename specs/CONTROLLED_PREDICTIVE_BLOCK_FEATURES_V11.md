# V11：固定特征块与活跃状态滑动中间结果

本协议在 V11 真实开发实例运行前固定。V10 保持了 V9 的语义，但逐标量访问和全闭包棋盘缓存没有节省总成本；重复棋盘只占约 2%–3%。V11 改变计算粒度与临时存储范围，以同期 V9 为主要对照。

## 固定输入与方法范围

[V11 名册](../reports/controlled_predictive_cohort_roster_v11.json)原样保留 V10／V9 的全部 16 个原始根、主场景与三个整族留出场景、34 个场景／实例。每项运行种子 `832101,832102,832103`；每合法动作行 256 次观测，原六查询库加四探测查询、原 horizon、每例 30,000 状态完整闭包上限不变。

每个原始实例／种子只采样一个经验核，共 48 个，供全部方法和场景复用。来源仍为原 V8 约束拟合器，每场景／种子一次，合计 12 次，仅接收该场景声明来源。目标适配与从头规则只读取当前目标经验奖励、后继分布及棋盘；查询和精确最优标签不参与构建。

固定 31 特征值、合法动作与终态语义、分割准则和顺序、阈值、编码编号、共享原编码补丁、未访问编码保留、自底向上传播、未解决冲突处理与最终一次聚合均保持 V9。纯签名组不为常量树审计补全特征；混合签名组继续使用全部原特征。V10 原实现与负面结果保留，不在本轮重跑或改写。

## 五个固定特征块

使用固定五块：原棋盘的七个特征，以及按原动作顺序排列的四组动作后特征，每组六个。来源树读取某个特征时，只计算它所属的完整特征块，并复用该状态已算的块。实际冲突组通过一次批量入口补齐剩余块，返回原顺序的 31 维元组，不经过 31 次逐标量惰性索引。

特征块按固定下标列表保存，不建立每标量字典。相对 V10，这可能多计算同一块中暂未被路径请求的特征；多计算量也完整报告，不预设较少特征必然更快。

profile 从棋盘直接确定语义，保留 V8 的终态处理：WON 优先，horizon 0 在首次合法动作后返回 CUTOFF，所有动作无变化才为 LOST。终态不创建持久特征上下文。ACTIVE 的四次确定性滑动用于建立合法动作集合，并保存为该状态的局部中间结果，供来源路径、混合组补全和最终规则编码复用。

没有以棋盘为键的全闭包字典，也没有跨状态、horizon、方法、实例、场景或种子的计算缓存。相同棋盘出现在另一状态记录时重新 profile；这项放弃的复用也在实际滑动计数中体现。从头与来源适配采用相同基础设施。全部目标动作行仍接受经验签名检查和一次最终聚合。

独立运行编码器只接收棋盘与 horizon，临时建立一个状态的特征上下文，按规则路径计算特征块。可移植格式继续为 V7 规则、有限动力学及编码对照，不携带滑动中间结果或完整状态查表。

## 八组同期比较与语义验证

八组为完整状态经验模型、零容差精确经验商、冻结来源规则（原 V8 运行实现）、V9 从头目标、V9 来源适配、V11 从头目标、V11 来源适配、V11 适配后动作后果打乱控制。前七组轮转构建顺序；控制最后构建，复用已适配规则，在打乱整条动作观测行后用 V11 独立编译，不重新适配。

全部八组的十查询策略冻结后，逐项比较同期 V9／V11 规则 payload、compiled cells／rows／roots／mapping、编码对照和十查询动作／值／规划计数的精确相等性。随后生成精确参考与真实完整策略审计。语义检查单独计时，差异原样留存，不以容差、重跑或实例筛选消除。

质量结果保留主场景原来源拟合分组和整族留出目标的单独分母，报告根首步、根完整策略、全部活跃状态的真实收益／失败／成功／目标值、必要查询切换、相对完整状态新增损失。已有同特征经验冲突和共有采样错误继续留存。

## 完整成本和临时存储

报告构建＋1／6／10 查询、加当前采样与分摊来源拟合、单目标独立承担全部额外来源获取／拟合的成本，以及公共闭包、预测与真实审计。来源拟合只归因给冻结来源、V9／V11 来源适配和控制，按场景声明的 16 或 6 例分摊；从头方法不承担来源拟合。当前目标若本身为来源，其获取成本不重复计算。

缓存或特征上下文的创建、填充、批量补齐、计数和最终编译均在各自构建内计时。计数包括状态 profile、创建的 ACTIVE 上下文、终态上下文零创建、特征块总数及全局／动作块计算量、实际标量计算、源路径读取、完整向量补齐、确定性滑动、签名检查与聚合行。计数按实际块计算批量更新，不把未做的标量访问当作工作。

记录构建中累计创建的上下文和保存的滑动结果总量；适配需持有全部 ACTIVE 状态上下文到构建结束，单独运行编码或顺序编译可逐状态释放。累计条目计数不称作并发驻留量或完整 Python RAM 字节数。不得出现对象引用环或跨方法预热。

打乱控制的独立方法成本包含复用的 V11 适配准备及自身打乱／编译，实际全轮只计一次共享准备。闭包和经验核按物理执行记一次，跨场景另记逻辑使用。库存序列化、语义比较、精确参考和事后解释单列。单轮串行测量，不重复运行后选择最小值；V10 历史墙钟不作为同期优化幅度。

针对性测试覆盖五块值和顺序、纯组不补齐、来源路径只取所需块、批量补齐避免逐标量访问、终态零上下文、跨状态无共享及及时释放、V9 规则／模型／冲突保持、输入与计费范围。测试及有界实现审查通过后执行唯一一轮固定比较，保留全部超预算、语义差异与未解决项，不按结果追加配置或计时运行。

固定导出主场景、`v6_spawn_edge_rescue_2`、种子 832101 的 V11 适配运行模型。一次新进程使用 V11 编码器查询收益 1、风险 0.3、目标 0.2，与进程内同一模型比较，并与已有 V9 产物核对 payload。保存结果 JSON、日志、stderr、运行模型、重载输出及说明，不增加无用途的哈希文件。
