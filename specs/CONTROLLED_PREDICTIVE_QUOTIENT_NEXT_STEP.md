## 1. 补足有辨识力的开发问题

在公开开发实例中加入两类情形：收益与失败风险存在实际权衡，且改变查询权重会改变最优动作；短期奖励相近，但后续动作或失败概率不同。保留普通实例，明确标注专门构造的机制挑战，不能将挑战集合当作自然开局分布。

使用与 V1 相邻的短 horizon 扩展，保持逐实例完整枚举的预算界限。reference 用于开发上限和有限审计；在选定生成规则后，全部生成实例进入报告。超预算和找不到预期冲突的情况也记录，不按候选表现替换实例。

划分表示训练、模型选择用的验证、最后一次开发评估三部分。按生成来源及其状态闭包处理交叉重叠，不能将同一棋盘换 ID 或换剩余步数称作未见状态。既有 V1 三个实例作为已见回归实例。

在这一步测 reference 的压缩与规划后果，确认测试确实要求不同策略。如果 reference 接近完整状态，结论只限于相应 horizon、固定动作与误差要求，不能宣称所有抽象都不可能。

## 2. 学习可执行的编码规则，替代完整棋盘查表

表示训练只使用训练部分的动作条件样本。第一版可用小型决策树或有限谓词分割，学习从棋盘观测到 cell 的规则；目标是保留各动作的奖励、失败／成功及后继 cell 分布。选择可检查的简单函数族，先判断学习问题是否成立。

状态编码保留终态、合法动作与剩余 horizon 的语义。连续抽象推演依然只使用 cell 与编译转移，不能在每一步模拟中重新查询真实棋盘。编码器和分割超参数在最后开发评估前固定。

首版将“状态表示的复用”与“动力学零样本迁移”分开测。对新的评估实例，允许两个主要组读取同一批、同预算的动作转移样本，并各自构建一次动力学：完整状态组按状态建模；候选使用冻结的编码规则聚合。随后二者使用模型完成多个查询。此设置检验未见棋盘上的抽象规则迁移和条件规划质量，不将重新估计转移的结果写成零样本世界模型迁移。

## 3. 完成同信息量的规划比较

主比较仍为同一批采样转移上的完整状态模型与新编码器商模型。保留 V1 查表商作为开发参考、动作后果打乱作为机制控制、精确 reference 作为有特权信息的上限。旧 U005 继续作为原任务上的历史失败记录，其 classifier 不被强行转换成 planner。

对每个实例构建一次，然后改变查询并重新规划。除收益／风险预测误差、实际目标差、活跃 cells 与展开量外，显式报告动作是否应随查询改变、是否改变正确，以及真实棋盘到 cell 的编码规则和存储开销。按实例和生成来源报告，避免只用一个全局平均值掩盖失败。

构建、编码、规划、审计的成本完整计入。使用一组预先声明的查询工作量观察总成本是否随复用改善，不能只报告单次 DP 更快。保存紧凑模型并在单独进程重新加载后回答新查询，以落实可复用模型的交付要求。

## 4. 将预测冲突变成局部修复对象

先输出具体冲突：同一 cell 中哪些状态、哪个动作、哪段后续推演造成收益或风险不一致。将采样误差与合并误差分开：完整状态经验模型也错的部分不能全部归咎于压缩。

表示修改和局部细化只用训练／验证反例，固定后在最后开发评估上检验。该评估暴露的问题保留为结果，不能修完后仍称同一批数据为独立评估。初版先建立可解释反例，不因此另造一套 assurance、留存或进程审计系统。
