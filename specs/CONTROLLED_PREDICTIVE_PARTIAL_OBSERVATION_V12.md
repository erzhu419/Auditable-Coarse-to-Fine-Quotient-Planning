# V12：部分目标观测与按查询构建

本协议在 V12 开发实验运行前固定。V9–V11 已恢复声明查询的策略后果，但全部目标动作行仍需获取和处理；特征访问优化没有获得总成本优势。V12 改变目标观测范围，检验查询引导是否能以较少观测保持完整策略质量，以及来源规则是否值得额外获取和拟合成本。

## 固定范围与预算

沿用 V11 的全部 16 个已暴露根、原 horizon、四个来源场景和 34 个场景／实例，种子 `832101,832102,832103`。原十个查询的权重和顺序不变，**本轮十个查询均参与观测选择**，不再把后四个称为独立探测查询。没有新增实例、旋转、筛选或正式科学 Gate。

每个已申请状态／动作行返回 256 次随机观测的聚合结果。四个部分观测方法各运行一条逐步获取轨迹，在累计 **8、32、128 行**处保留三个检查点；查询间共享本方法已获取的数据。预算是绝对行数，不读取完整目标闭包来计算预算百分比。若所有查询的经验区间已闭合，或广度优先方法已无可申请行，可提前停止；未用预算不填充。每方法／目标／种子独立获取，不跨方法预热数据或运行缓存。

同一棋盘、剩余步数、动作及种子的观测流与申请顺序无关。按字母顺序排列动作，以 `B=12**16`、`board_code=sum(rank[i]*12**i)`，用 `seed*(16*B)+(h*4+action_index)*B+board_code` 初始化该行的随机数生成器。当前 ACTIVE 棋盘 rank 不超过 10，h 不超过 3。它是行流的整数编号，不新增校验或指纹文件。本轮行流不同于 V9–V11 的全模型顺序随机流，不能将跨版本差异归因于方法。

## 信息边界与回退

部分规划器只接收根棋盘、horizon、查询和逐行观测接口。它可对实际见到的棋盘计算合法动作、终态、确定性滑动奖励；这些 profile 和滑动计入构建。接口内部只枚举当前申请行的 `step_v1` 支持并采样，不建立目标全闭包。完整支持不返回规划器，接口的枚举和采样耗时、支持条目、样本和返回后继条目完整计数。

未申请动作保留为未知，不能删除合法动作，也不能把未展开的 h>0 状态当作 CUTOFF、LOST 或已知动力学。已观测行按其经验概率递推。对未知动作，令确定性即时奖励为 r，下一步棋盘质量上界为当前 tile mass 加 4，剩余 t=h-1 步；未来合并奖励上界为 `(t*M+2*t*(t-1))/2048`。本轮权重均非负，故动作下界为 `reward_weight*r-failure_penalty`，上界为 `reward_weight*(r+future_bound)+goal_bonus`。WON、LOST、CUTOFF 依原语义分别取 goal bonus、负 failure penalty、0。

状态上下界分别取合法动作下界和上界的最大值。冻结执行策略选择最大下界动作，平局按动作字母序。未记录棋盘／horizon 使用固定的即时合并奖励贪心回退，平局也按字母序；回退不申请额外样本、不使用完整状态最优动作。已记录但选择未观测动作、与完全未记录位置的回退分别统计。执行策略对任意真实可达 ACTIVE 棋盘都可计算。

这些区间只界定未观测部分的保守补全，已观测概率使用经验频率；**它们不是对真实动力学的统计置信区间**。经验区间闭合不代表真实策略无损。真实完整策略、样本误差和未观测分支损失在冻结后独立审计。

## 四个同预算方法与完整基线

1. `bfs`：只在已见到的状态中，按 h 降序、棋盘字典序、动作字母序申请未知行；每次返回的样本后继加入观测状态集。
2. `query_interval`：按固定十查询顺序循环，每次为一个尚未闭合的查询申请一行。沿当前最大上界策略传播已观测后继的到达概率，在未知动作前沿选择“到达概率 × 动作区间宽度”最大的行。动作上界或前沿优先级平局按稳定棋盘／动作顺序处理。每次获取后重新递推，不预设搜索调度更便宜。
3. `source_priority`：目标模型、上下界、预算、停止和最终动作规则均同第 2 组。来源模型的动作 Q 值仅改变上界动作平局和前沿优先级平局的顺序，不能填入目标奖励或转移。
4. `shuffled_source_priority`：同第 3 组，按来源 code 内的合法动作顺序把来源动作 Q 值循环移位一格。来源获取／拟合共享一次物理工作，各来源方法承担相同归因成本。

来源仍只用各场景声明来源的完整经验观测，采用原 V8 约束编码器。把来源有限模型重编号后合并，用同一编码器汇集来源经验行，并为十查询计算 code／动作 Q。目标回调按棋盘和 horizon 执行来源规则；未见 code 或动作返回中性优先值 0。每个来源方法的运行缓存独立。来源 acquisition、完整支持构建、拟合、编译和十查询准备全部计费。目标恰为来源的训练项单独保留，不能作为迁移成功证据。

另保留 **完整状态经验模型和零容差精确经验商**，从全部目标合法行读取相同编号观测流。两者共享一次物理获取，各方法成本归因均包含完整获取；它们是全行成本／质量基准，不称作 8／32／128 行的匹配预算方法。完整经验模型还包含未被 256 个样本命中的支持状态，其完整支持构建成本计入。完整基线及来源获取复用已支付的闭包支持进行随机抽样，不再次调用 `step_v1` 枚举相同行；支持顺序、行流种子和抽样结果须与部分接口一致。真实支持只用于产生观测，经验频率进入拟合与规划。

## 冻结、质量和成本

每个场景／目标／种子的四个部分方法、三个预算、十查询策略先全部冻结，然后才获取该目标完整闭包并构建两个全行基线；最后计算精确参考和真实策略后果。来源实例已有闭包也不得传入部分规划器。源码测试使用小型人工夹具；真实名册只执行一轮，不按结果重跑、选最优计时或追加预算。

质量保留根首步与完整策略最优率、真实 reward／failure／success／value、相对全行经验模型的新增损失、全状态策略审计和最坏反例。根策略的真实占用概率用于统计未记录状态回退、未观测动作执行的期望次数和触达概率；概率是冻结后的审计指标，不反馈观测选择。所有真实可达未观测状态均由固定回退策略决定动作，不用精确参考替它补齐。

报告各预算实际申请行数、256 倍样本数、已发现状态、返回经验后继、接口支持枚举和构建递推工作。构建墙钟包含观测接口、目标 profile、区间／前沿重算、来源优先回调以及策略快照；如序列化另行计时，明确范围。来源成本同时给出按场景目标数分摊和单目标独立承担口径。各部分方法独立重新执行观测，所以目标本身为来源时，完整来源获取与目标局部再次获取均实际计费，不减去尚未观测的来源行。只有真实共享的闭包／拟合等操作在物理总数中计一次；相同行流再次抽取不算共享。真实数据收集的物理总数与方法归因总数分别报告。

回退不消耗额外目标样本。对完整审计枚举全部状态的策略查表／回退计算实测计时，单列为审计执行成本；同时报告根分布下预期回退次数和滑动数，不把离线全状态枚举墙钟冒充线上延迟。精确参考、后果审计、结果序列化单列。来源、回退和调度成本都不能因观测行变少而省略。

## 交付与判断

保留协议、输入名册、针对性测试、全部预算结果、日志和 stderr。导出主场景 `v6_spawn_edge_rescue_2`、832101、128 行 `source_priority` 的冻结十查询执行策略与回退定义，并在新进程对声明查询重载验证；它是本轮部分策略产物，不冒称已有完整商动力学或任意新查询的可移植模型。

少取数据只有在真实完整策略与完整成本一起改善时才支持替换基线。来源优先必须分别超过无来源查询方法和打乱来源控制，且单列来源未参与拟合的目标。失败、预算耗尽、区间未闭合和采样错误全部保留。U005 FAIL、U006 未启动、原 V2 的 24 个延期候选保持；V12 只是已暴露材料上的探索性开发比较。
