# V230：联合置信区域与候选感知获取资格

本阶段先检验 V229 查询缺证的统计主因，环境新增观察为0。V229 的负 Gate 不重判；新置信事件是在看过 V229 后提出的探索性设计。

固定失败例为 `(life,index)=(0,58),(1,58),(2,42),(2,44),(4,44),(4,58)`，沿用 V229 诊断的选择。每例另取同 life、同 stage 最早的 REPAIR_CS 查询获证目标作为正对照。只读取来源与既有目标记录，不生成缺失后缀。

联合 CS 对每个 categorical row 使用 Dirichlet(1/2,…,1/2) 混合似然比。每臂每 life 的 member 72×3条流分配δ=.025，A的3×3真实池分配δ=.0125，B同样δ=.0125；threshold分别为8640、720、720，总δ=.05。来源是对应池的初始前缀。此事件重新冻结，不声称由旧7类别边际事件推出。

查询选中的策略、误差阈值.05、执行阈值2、risk阈值.05、batch16和目标cap384保持不变。每条策略差在同一个核上评估。二类别算子取联合CS投影端点，DETOUR三类别保持联合约束；线性support用可行弱对偶见证计算向外上界，求解器仅建议见证。

资格分三层：

- `PUBLIC_SOURCE_MEMBER`：公开来源全部三个候选，每候选仅与当前成员CS相交。没有使用真归属或旧事件下的mask，不代表完整累计修订方法。
- `ORACLE_SOURCE_MEMBER`：仅用于分解类型识别损失，给出真来源索引。
- `ORACLE_CUMULATIVE_POOL`：仅用于分解类型内精度，以真归属将当前成员及此前同情境同类型成员放入来源池。保留实际计数，禁止宣称为已实现的获取算法或性能上界。

另在六个失败例spent256的实际前缀上比较旧获取与新候选感知获取。forecast使用V229同一冻结库和原证书；每个唯一来源索引提供一个在当前候选盒内的确定性核，按16、64、剩余cap三个窗口预测。候选数不按分支数加权。所有forecast丢弃，不计作环境数据，也不声称产生新的完成率。

必要验证只针对会改变结论的失败：新事件在真核上超界；真核regret超过认证上界；support的向外见证错误；forecast提交假数据、越过cap或改变停止；读取旧记录时漏收费或将oracle当成公开模型。资格后再决定是否实现完整联合归属池并冻结新付费对照。

## 小规模实际续采（首次新增观察之前冻结）

六个失败例均从 V229 已付费spent256前缀开始，比较 `OLD_V229` 与 `CANDIDATE_MULTI`；两臂保持同一个固定旧库、原V229证书与实际停止条件，不提交或更新库。唯一方法差异是获取选择。每算子使用新的独立后缀seed `260000+(life*78+index)*3+operator_index`，两臂分别读取相同潜在流的各自前缀；它们的实际读取分别收费，不共用免费的观察。batch16，原总cap384，至多每臂每例补128、合计1536条新增观察。

每条路线列出256条当前目标前缀、到该目标时已发生的来源/旧目标费、新后缀费与模型计算时间。旧库为固定输入，不从oracle类型更新。决策冻结后才计算真实regret。报告六对的完成、证书变化和观察成本，不能推断生命周期Gate通过或总体统计优势。

对仍缺证的oracle联合区域，另尝试为四个纯策略分别构造一个区域内regret>.05的完整核；B反例还加入未变化算子的A真来源与A累计池联合约束。只有逐约束精确有理数验证通过的核才留为反例。这能区分数值support求解松弛与区域本身不能认证，但不证明其他CS或混合查询策略也不可能。
